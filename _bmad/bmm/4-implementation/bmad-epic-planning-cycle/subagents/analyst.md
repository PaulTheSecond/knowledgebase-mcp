# Analyst Subagent — Epic Creation (New Feature)

## ОБЯЗАТЕЛЬНО ПРОЧИТАТЬ В НАЧАЛЕ
> Пути берутся из блока **RESOLVED CONTEXT** в промпте — `config.yaml` не читать.

1. Существующие эпики в `{epics_dir}` — для понимания формата и нумерации
2. PRD (sharded): `docs/{activeContext}/prd/` — для контекста требований
3. Архитектура: `{architecture_dir}` — для технического контекста

## СКИЛЛЫ
Используй при необходимости:
- **impactos-frontend-standards** — код-стайл Angular и дизайн-токены (@tribetech-org/common)
- **impactos-frontend-packages** — фронтенд-библиотеки Auth и UI (@tribetech-org/auth, @tribetech-org/ui)

## ВЫПОЛНИ СТРОГО ПО ПОРЯДКУ

### Шаг 1: Анализ требований
- [ ] Понять бизнес-потребность (из задания пользователя)
- [ ] Изучить существующую кодовую базу (что уже есть)
- [ ] Определить scope фичи (что входит, что НЕ входит)
- [ ] Выявить зависимости от других компонентов/эпиков

### Шаг 2: Исследование кодовой базы
- [ ] Найти существующие компоненты, которые затрагивает фича
- [ ] Определить модели данных, которые нужно создать/изменить
- [ ] Определить API-контракты (если применимо)
- [ ] Оценить влияние на существующий функционал
