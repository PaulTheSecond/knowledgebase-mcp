## ОТЛИЧИЕ ОТ POST-DEV ОБНОВЛЕНИЯ
Это обновление архитектуры **ДО разработки** (planning phase), а не после.
Цель — подготовить архитектурные документы к предстоящим изменениям:
- Документировать ПЛАНИРУЕМЫЕ изменения (не реализованные)
- Обновить модели данных (если появляются новые интерфейсы)
- Обновить API-контракты (если меняются)
- Добавить секцию "Planned Changes" в релевантные документы

## ВЫПОЛНИ СТРОГО ПО ПОРЯДКУ

### Шаг 1: Анализ влияния эпика на архитектуру

- [ ] Добавить/обновить описания изменяемых контрактов
- [ ] Документировать BE ↔ FE маппинг (если применимо)

### Шаг 4: Обновление `docs/{activeContext}/architecture/project-structure.md`
Если эпик добавляет новые файлы/папки:
- [ ] Добавить планируемые файлы в структуру
- [ ] Обновить описания компонентов

### Шаг 5: Обновление `docs/{activeContext}/architecture.md` (entry point)
- [ ] Добавить ссылку на эпик в секцию "Planned/In Progress"
- [ ] Обновить обзор если меняется высокоуровневая архитектура

### Шаг 6: Обновление `docs/{activeContext}/README.md` (навигационный файл) — ОБЯЗАТЕЛЬНО
**Всегда создавать/обновлять** — это главная точка входа в документацию контекста.

Структура README.md (адаптировать под текущий контекст):
```markdown
# Backend документация

Документация backend части проекта **{namespace}**.

## Навигация

### Основные документы
| Документ | Описание |
|----------|----------|
| [Архитектура](architecture.md) | Сводка архитектурных решений |

### Архитектура (детально)
| # | Раздел | Описание |
|---|--------|----------|
{ссылки на файлы из docs/{activeContext}/architecture/}

### Epics
| Epic | Статус | Описание |
|------|--------|----------|
{все эпики из docs/{activeContext}/epics/ с реальными статусами}

### Stories
{по секции на каждый эпик с таблицей story файлов и статусами}

---

## Быстрый старт разработки
{инфраструктура (docker команды), миграции, запуск}

## Ключевые файлы
{таблица ключевых файлов проекта}
```

Правила:
- Если `README.md` не существует → **создать с нуля**
- Если существует → **обновить**: добавить ссылки на новые файлы эпика, обновить статусы stories
- Включать ВСЕ story-файлы из текущего и предыдущих эпиков
- Статусы: 🔵 Ready For Develop | 🟡 In Progress | ✅ Done | ⏸️ Deferred

## ПРАВИЛА
1. **Планируемые изменения** — помечать как "Planned: Epic {N}" (не как факт)
2. **Минимальные изменения** — только то, что относится к эпику
3. **Consistency** — следовать существующему стилю документов
4. **Не изобретать** — документировать только то, что описано в эпике
